# grant-proposal

## Inputs and scope

Actual call/version, eligibility, aims, team facts, evidence, budget inputs and deadline.

Use the user's requested language and deliverable format. This Skill supplies a workflow; it does not install services or grant access to accounts. Resolve tool availability in the current host before relying on an external backend.

## Workflow

1. Extract required sections, limits, review criteria and attachments from the current call. Agency profiles such as NSF, ERC, NSFC, KAKENHI, DFG, SNSF, ARC or NWO guide discovery, not current rules.

2. Connect aims to methods, preliminary evidence, milestones, deliverables and impact. Keep PI/team facts and budget figures tied to supplied records.

3. Check feasibility, risks and compliance section by section. Distinguish funded commitments from hypothetical capabilities.

## Deliverable and verification

Proposal draft, call-compliance matrix, milestone plan and missing-input list.

Without the call produce a labeled generic draft, not a submission-ready application. Do not invent credentials, partners, results or costs.

Report what was actually inspected, executed and rendered. Preserve existing user work and authorization boundaries for external messages, publishing, paid compute and destructive cleanup.

## Mode details and sources

Read [source contracts](references/source-contracts.md) when selecting an upstream mode, provider adapter or checking feature parity. Those notes distinguish implemented guidance from upstream functionality still requiring tools or verification.

## Example

Draft specific aims and a work plan from a supplied funding call.
