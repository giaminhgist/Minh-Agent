# manuscript-writing

## Inputs and scope

Audience/venue, paper stage, evidence, contributions, existing text and language.

Use the user's requested language and deliverable format. This Skill supplies a workflow; it does not install services or grant access to accounts. Resolve tool availability in the current host before relying on an external backend.

## Workflow

1. Choose outline, section, full draft, abstract or systems-paper mode. Establish the claim/evidence/story structure before expanding prose.

2. Write at the requested level with source-anchored statements, consistent notation and a figure plan. For systems papers connect design choices to evaluation and resource tradeoffs.

3. Keep unknown results and citations explicitly unresolved. For bilingual text preserve meaning, names, equations and citation anchors rather than literal phrasing.

4. Check narrative consistency and deliver the requested editable format.

## Deliverable and verification

Draft or outline, claim/evidence map, figure plan and unresolved-input list.

Do not write plausible numerical results or bibliography entries to complete a narrative. Formatting and full build are separate steps.

Report what was actually inspected, executed and rendered. Preserve existing user work and authorization boundaries for external messages, publishing, paid compute and destructive cleanup.

## Mode details and sources

Read [source contracts](references/source-contracts.md) when selecting an upstream mode, provider adapter or checking feature parity. Those notes distinguish implemented guidance from upstream functionality still requiring tools or verification.

## Example

Draft a methods section from code and a results outline from supplied tables.
