# paper-reading

## Inputs and scope

Paper identifiers or files, desired depth and questions.

Use the user's requested language and deliverable format. This Skill supplies a workflow; it does not install services or grant access to accounts. Resolve tool availability in the current host before relying on an external backend.

## Workflow

1. Resolve the paper version and record whether you accessed full text, sections, abstract or an external overview.

2. Trace problem, assumptions, method, experiments and conclusions to sections or pages. Check whether figures and ablations support the key claim.

3. Use AlphaXiv or DeepXiv when available as navigation aids; compare their summaries with primary content. Explain equations or implementation implications at the requested depth.

## Deliverable and verification

Reading notes with source anchors, method reconstruction, evidence gaps and follow-up questions.

When full text is inaccessible, limit the analysis explicitly; never fabricate methods from a title or summary.

Report what was actually inspected, executed and rendered. Preserve existing user work and authorization boundaries for external messages, publishing, paid compute and destructive cleanup.

## Mode details and sources

Read [source contracts](references/source-contracts.md) when selecting an upstream mode, provider adapter or checking feature parity. Those notes distinguish implemented guidance from upstream functionality still requiring tools or verification.

## Example

Explain a paper's main algorithm and which ablation supports its central claim.
