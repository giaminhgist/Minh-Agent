# rebuttal-and-response

## Inputs and scope

Reviewer comments, manuscript versions, venue response constraints and evidence.

Use the user's requested language and deliverable format. This Skill supplies a workflow; it does not install services or grant access to accounts. Resolve tool availability in the current host before relying on an external backend.

## Workflow

1. Split comments into identifiable issues and classify clarification, correction, new analysis or disagreement.

2. Draft a direct response with evidence and exact revised locations. For disagreement explain the technical basis respectfully rather than promising unsupported changes.

3. Audit every claimed revision against the actual manuscript and distinguish planned work from completed work.

4. Fit the response limits without losing the answer to each issue.

## Deliverable and verification

Response letter, comment/change matrix and unresolved requests.

Do not claim an experiment was run or text was changed unless verified; do not submit responses automatically.

Report what was actually inspected, executed and rendered. Preserve existing user work and authorization boundaries for external messages, publishing, paid compute and destructive cleanup.

Draft a rebuttal with links to changed sections and two clearly deferred experiments.
