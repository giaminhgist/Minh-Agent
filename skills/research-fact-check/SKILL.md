# research-fact-check

## Inputs and scope

Atomic claims, context, date/jurisdiction when relevant and source access.

Use the user's requested language and deliverable format. This Skill supplies a workflow; it does not install services or grant access to accounts. Resolve tool availability in the current host before relying on an external backend.

## Workflow

1. Split compound claims and preserve qualifications and time scope.

2. Seek primary evidence and inspect the relevant passage or data; use independent corroboration where it materially changes confidence.

3. Classify supported, contradicted, mixed or unverified and explain the evidence-to-claim relation.

4. Suggest precise corrections without extending beyond the evidence.

## Deliverable and verification

Claim ledger, source anchors, verdicts and corrected wording.

Unavailable evidence yields unverified rather than false; a source repeating a claim does not establish it.

Report what was actually inspected, executed and rendered. Preserve existing user work and authorization boundaries for external messages, publishing, paid compute and destructive cleanup.

## Mode details and sources

Read [source contracts](references/source-contracts.md) when selecting an upstream mode, provider adapter or checking feature parity. Those notes distinguish implemented guidance from upstream functionality still requiring tools or verification.

## Example

Fact-check three factual statements in a proposal and correct overbroad wording.
