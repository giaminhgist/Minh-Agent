# research-memory

## Inputs and scope

Existing notes, sources, project identifiers and update scope.

Use the user's requested language and deliverable format. This Skill supplies a workflow; it does not install services or grant access to accounts. Resolve tool availability in the current host before relying on an external backend.

## Workflow

1. Inspect the current organization before adding notes; avoid a parallel duplicate wiki.

2. Separate source facts, interpretations, hypotheses and decisions; preserve identifiers, versions and source anchors.

3. Merge new evidence with explicit conflict handling and record superseded conclusions rather than silently replacing them.

4. Produce a concise resume note pointing to authoritative artifacts and unresolved questions.

## Deliverable and verification

Updated notes/index, evidence links, decision history and resume context.

Do not store credentials or unsupported facts as established knowledge; inaccessible sources remain labeled.

Report what was actually inspected, executed and rendered. Preserve existing user work and authorization boundaries for external messages, publishing, paid compute and destructive cleanup.

## Mode details and sources

Read [source contracts](references/source-contracts.md) when selecting an upstream mode, provider adapter or checking feature parity. Those notes distinguish implemented guidance from upstream functionality still requiring tools or verification.

## Example

Consolidate paper notes and experiment decisions into a searchable project memory.
