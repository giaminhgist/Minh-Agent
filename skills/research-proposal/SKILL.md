# research-proposal

## Inputs and scope

Problem, target audience, prior work, resources, timeline and institutional template if any.

Use the user's requested language and deliverable format. This Skill supplies a workflow; it does not install services or grant access to accounts. Resolve tool availability in the current host before relying on an external backend.

## Workflow

1. Anchor the problem in evidence and state the exact gap relative to closest work.

2. Build a method thesis linking mechanism to expected outcomes; define contributions as hypotheses until tested.

3. Specify evaluation, baselines, ablations, failure criteria, resources and milestones. Run a refinement pass for mismatches between claims and feasible evidence.

4. Follow a supplied thesis/PhD template explicitly; do not assume a generic proposal satisfies institutional rules.

## Deliverable and verification

Technical proposal, claims-to-tests map, risk register and experiment handoff.

Missing preliminary evidence remains a stated gap; route funding-specific forms to grant-proposal.

Report what was actually inspected, executed and rendered. Preserve existing user work and authorization boundaries for external messages, publishing, paid compute and destructive cleanup.
