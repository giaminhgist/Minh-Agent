# research-review

## Inputs and scope

Manuscript/proposal, review mode, methodology, prior reviews and available evidence.

Use the user's requested language and deliverable format. This Skill supplies a workflow; it does not install services or grant access to accounts. Resolve tool availability in the current host before relying on an external backend.

## Workflow

1. Choose full, quick, methodology, adversarial, re-review or bounded iterative review. Read the supplied artifact before commissioning new research.

2. Assess problem/contribution, validity, evidence, clarity and limitations with concrete source anchors. In adversarial mode record attack, defense and unresolved adjudication separately.

3. For re-review compare each response to changes in the actual manuscript. For iterative review preserve issue state and stop when evidence is exhausted or the agreed budget is reached.

4. Use only available reviewer backends; report self-review, context-separated review or external model review accurately.

## Deliverable and verification

Review with supported strengths, actionable weaknesses, severity and revision criteria.

Scores do not establish truth or independent validation. Backend substitution and missing evidence must be disclosed.

Report what was actually inspected, executed and rendered. Preserve existing user work and authorization boundaries for external messages, publishing, paid compute and destructive cleanup.

## Mode details and sources

Read [source contracts](references/source-contracts.md) when selecting an upstream mode, provider adapter or checking feature parity. Those notes distinguish implemented guidance from upstream functionality still requiring tools or verification.

## Example

Re-review whether a revised paper actually addresses the reviewers' concerns.
