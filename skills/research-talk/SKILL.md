# research-talk

## Inputs and scope

Paper/materials, audience, duration, slide constraints and existing deck.

Use the user's requested language and deliverable format. This Skill supplies a workflow; it does not install services or grant access to accounts. Resolve tool availability in the current host before relying on an external backend.

## Workflow

1. Choose build, polish-existing or end-to-end mode. Define a timed narrative and claims supported by the paper.

2. Create or revise editable PPTX/Beamer slides, reusing real figures and preserving citations. Keep speaker notes and spoken script aligned with slides.

3. Inspect rendered slides for overflow, figure readability, anonymity and consistency; estimate pacing from actual content.

4. Deliver source, rendered output and presenter material, noting exports not performed.

## Deliverable and verification

Editable deck, PDF/previews when rendered, notes/script and timing/QA record.

A Markdown outline is not a finished deck; missing presentation/TeX tooling must be reported.

Report what was actually inspected, executed and rendered. Preserve existing user work and authorization boundaries for external messages, publishing, paid compute and destructive cleanup.

## Mode details and sources

Read [source contracts](references/source-contracts.md) when selecting an upstream mode, provider adapter or checking feature parity. Those notes distinguish implemented guidance from upstream functionality still requiring tools or verification.

## Example

Turn a paper into a ten-minute talk with notes and readable figures.
