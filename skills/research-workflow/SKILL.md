# research-workflow

## Inputs and scope

Project goal, entry stage, existing artifacts, milestones and authorized actions.

Use the user's requested language and deliverable format. This Skill supplies a workflow; it does not install services or grant access to accounts. Resolve tool availability in the current host before relying on an external backend.

## Workflow

1. Inventory evidence and determine the current stage from artifacts rather than chat claims.

2. Define stage inputs, outputs, owners and acceptance checks; permit mid-entry when prerequisites are genuinely satisfied.

3. Track decisions, review obligations and failure states. Invalidate dependent claims when upstream data or methods change.

4. Save a resumable handoff with paths, versions, completed evidence and the next unblocked action.

## Deliverable and verification

Project state, artifact/dependency ledger, gate results and resume plan.

This bundle's state format is not the full ARS Material Passport wire schema; disclose that interoperability gap.

Report what was actually inspected, executed and rendered. Preserve existing user work and authorization boundaries for external messages, publishing, paid compute and destructive cleanup.

## Mode details and sources

Read [source contracts](references/source-contracts.md) when selecting an upstream mode, provider adapter or checking feature parity. Those notes distinguish implemented guidance from upstream functionality still requiring tools or verification.

## Example

Resume a research project at paper writing while auditing which experiment evidence is available.
