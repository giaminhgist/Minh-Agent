# scoped-planning

## Inputs and scope

User outcome, existing artifacts, constraints, acceptance evidence and authorized scope.

Use the user's requested language and deliverable format. This Skill supplies a workflow; it does not install services or grant access to accounts. Resolve tool availability in the current host before relying on an external backend.

## Workflow

1. Inspect the existing context and separate unknown requirements from reversible choices. Offer alternatives only where their consequences differ materially.

2. For a design, define interfaces, data flow, failure paths and smallest useful milestone. Use a visual sketch when spatial relationships matter; do not require a browser service for plain text decisions.

3. For an execution plan, give ordered tasks with concrete file or artifact targets, dependencies and observable acceptance checks. Keep unresolved decisions visible and hand off only work already authorized.

## Deliverable and verification

Design rationale, ordered plan, assumption ledger and validation/handoff contract.

If required information is missing, ask the smallest question and continue independent analysis; never turn a plan into permission for deployment.

Report what was actually inspected, executed and rendered. Preserve existing user work and authorization boundaries for external messages, publishing, paid compute and destructive cleanup.

## Mode details and sources

Read [source contracts](references/source-contracts.md) when selecting an upstream mode, provider adapter or checking feature parity. Those notes distinguish implemented guidance from upstream functionality still requiring tools or verification.

## Example

Plan a reproducible paper-figure pipeline from a CSV dataset and existing LaTeX paper.
