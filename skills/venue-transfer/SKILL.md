# venue-transfer

## Inputs and scope

Current manuscript, previous submission context, target guidelines and permitted edits.

Use the user's requested language and deliverable format. This Skill supplies a workflow; it does not install services or grant access to accounts. Resolve tool availability in the current host before relying on an external backend.

## Workflow

1. Extract new scope, format, anonymity, length and disclosure requirements from current instructions.

2. Map changes to the existing contribution and evidence; distinguish formatting transfer from scientific revision.

3. Respect text-only or no-new-experiment constraints when specified and flag requirements that cannot be met within them.

4. Review terminology, citations, supplementary references and submission-package consistency.

## Deliverable and verification

Transferred manuscript, requirements/change map and unresolved submission conditions.

Do not infer that a new template makes the work venue-appropriate or submission-ready.

Report what was actually inspected, executed and rendered. Preserve existing user work and authorization boundaries for external messages, publishing, paid compute and destructive cleanup.

## Mode details and sources

Read [source contracts](references/source-contracts.md) when selecting an upstream mode, provider adapter or checking feature parity. Those notes distinguish implemented guidance from upstream functionality still requiring tools or verification.

## Example

Transfer a workshop paper to a journal while preserving a text-only revision constraint.
